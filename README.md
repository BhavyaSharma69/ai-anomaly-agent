# AI Anomaly Agent — Automated Business KPI Monitoring

An automated agent that reads business KPI data from Excel, detects statistically
significant anomalies against a rolling baseline, explains what changed in
plain English, and sends an email alert — turning a one-time analysis into a
continuous monitoring tool.

Built as a portfolio project to demonstrate practical, production-style
analytics: automation, statistical reasoning, and clear business communication
— not just a static EDA notebook.

## Problem

Teams don't want to manually open a spreadsheet every morning to check
whether revenue, traffic, or refunds moved abnormally. This agent watches
the data and surfaces what matters, before a manager has to find it manually.

## How it works

```
business_metrics.xlsx
        │
        ▼
 ┌─────────────────┐     1. Load & clean data
 │  anomaly_agent   │     2. Compare each metric to a rolling 14-day baseline
 │      .py         │     3. Flag deviations ≥ 2 standard deviations (z-score)
 └────────┬─────────┘     4. Cross-reference same-day anomalies for context
          │
          ▼
 ┌─────────────────┐
 │  report_pdf.py   │───▶  anomaly_report.pdf  (charts + summary + findings)
 └────────┬─────────┘
          │
          ▼
 ┌─────────────────┐
 │  email_alert.py  │───▶  Email alert with the PDF attached
 └─────────────────┘
```

## Detection method

- Baseline: rolling 14-day mean and standard deviation for each metric
- Anomaly threshold: z-score ≥ 2.0 ("moderate"), ≥ 3.0 ("high")
- Each flagged day is compared against the 14 days *before* it, so one
  anomaly doesn't distort the baseline used to catch the next one
- Anomalies flagged on the same day are cross-referenced — e.g. a traffic
  spike + conversion-rate drop on the same day is reported as a likely
  "traffic quality" issue rather than two unrelated line items

## Sample finding (from the included sample data)

> **Aug 07 — Traffic:** risen to 18,702.00 (+102.5% vs. the 14-day average).
> **Aug 07 — Conversion Rate:** dropped to 1.84 (-44.8% vs. the 14-day average).
>
> **Analyst note:** Traffic and conversion rate moved together — this pattern
> usually indicates a change in traffic quality (e.g. a campaign or referral
> source bringing in less qualified visitors) rather than a site issue.

See `anomaly_report.pdf` for the full sample report, including trend charts
with anomalies marked.

## Project structure

| File | Purpose |
|---|---|
| `generate_data.py` | Creates a synthetic sample dataset (`business_metrics.xlsx`) with realistic injected anomalies, for demo purposes |
| `anomaly_agent.py` | Core detection logic: loads data, computes baselines, flags anomalies, generates plain-English explanations |
| `make_charts.py` | Renders trend charts with anomalies marked in red |
| `report_pdf.py` | Assembles the findings + charts into a polished PDF report |
| `email_alert.py` | Sends the report as an email alert via SMTP |

## Running it

```bash
pip install pandas numpy openpyxl reportlab matplotlib

python generate_data.py     # creates sample business_metrics.xlsx
python anomaly_agent.py     # prints detected anomalies to console
python report_pdf.py        # generates anomaly_report.pdf
python email_alert.py       # sends the report by email (requires setup below)
```

### Email setup (optional, free)

Uses Gmail SMTP with an app password — no paid API required.

1. Enable 2-Step Verification on your Google account
2. Create an [App Password](https://myaccount.google.com/apppasswords)
3. Set environment variables (never commit these):
   ```bash
   export EMAIL_SENDER="you@gmail.com"
   export EMAIL_APP_PASSWORD="your_16_char_app_password"
   export EMAIL_RECEIVER="you@gmail.com"
   ```

## Notes on the sample data

`business_metrics.xlsx` is synthetic data generated by `generate_data.py`,
with a handful of realistic anomalies deliberately injected (a traffic
spike with a conversion-rate drop, a refund spike, a revenue dip) so the
detector has something real to catch. Swap in your own Excel export to
run it against real data.

## Possible extensions

- Swap the z-score baseline for an LLM call to generate richer, more
  nuanced explanations
- Add Slack/Teams alerting alongside email
- Store historical anomalies in a database to track recurrence over time
- Add a lightweight Streamlit dashboard for browsing past reports
